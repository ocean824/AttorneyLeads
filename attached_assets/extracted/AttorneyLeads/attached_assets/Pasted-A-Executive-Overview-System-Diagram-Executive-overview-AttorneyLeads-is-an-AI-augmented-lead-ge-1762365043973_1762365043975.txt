A) Executive Overview + System Diagram

Executive overview

AttorneyLeads is an AI-augmented lead-generation and light-CRM platform for criminal defense attorneys. It scrapes public Florida arrest records via a Python scraper, stores and normalizes them in Postgres via Drizzle ORM, enriches each record with OpenAI-powered charge classification and risk scoring, deduplicates and prioritizes high-value leads, and then syncs them into a CRM workflow that integrates with PhantomBuster (prospect discovery), Calendly (meeting scheduling), and Google Sheets (reporting & exports) — all running in a single Replit workspace (Node 20 + TypeScript + Express + React + Vite + Neon Postgres).

# Architecture

## High-Level Overview

AttorneyLeads is a single-workspace Replit app composed of:

- **React + Vite SPA (`client/`)**
  - Dashboard (jobs, analytics)
  - Arrest records browser
  - Duplicate management
  - CRM views (prospects, campaigns, meetings)

- **Express API Server (`server/`)**
  - HTTP API (`/api/**`) for scrape jobs, records, duplicates, analytics, CRM
  - Integrations:
    - **Neon Postgres** via Drizzle ORM (`server/db.ts`, `shared/schema.ts`)
    - **Python Scraper** (`server/scraper.py`) for county sites
    - **OpenAI** via `ai-service.ts`
    - **PhantomBuster**, **Calendly**, **Google Sheets**

- **Shared Schema (`shared/`)**
  - Drizzle schema & zod validation (`schema.ts`) shared by server and client.

## Module Boundaries

- `server/routes.ts`
  - Arrest record flows: stats, analytics, scraping, records, duplicates, AI test.
- `server/crm-routes.ts`
  - CRM flows: prospects, outreach, meetings, sheets/calendly sync.
- `server/storage.ts`
  - Data access via Drizzle; implements `IStorage` with methods grouped by domain.
- `server/ai-service.ts`
  - Encapsulates OpenAI calls for AI enrichment (charge classification, risk).
- `server/lead-scoring.ts`
  - Lead scoring+labeling utilities; stateless pure functions.

### Dependencies

- `client` → calls `server` via REST (`/api/**`)
- `server` → uses `shared/schema` and `db` (Drizzle)
- `server` → Python scraper via `child_process.spawn`
- `server` → external services via dedicated service modules

# AttorneyLeads – PRD MASTER

## 1. Scope & Vision

AttorneyLeads is a lead-generation and intake acceleration tool for criminal defense
attorneys. It turns public arrest records into prioritized, AI-enriched leads and
feeds them into a lightweight CRM workflow with outreach and scheduling.

### Out of Scope (for now)

- Full-blown law firm practice management.
- E-filing, billing, and matter management beyond basic lead tracking.

## 2. Personas

- **Criminal Defense Attorney (Primary)**
  - Needs a steady pipeline of qualified leads.
  - Values speed to contact and ability to filter by severity / location.

- **Intake Specialist / Coordinator**
  - Works daily in the dashboard.
  - Reviews leads, resolves duplicates, coordinates outreach and bookings.

- **Owner / Operator**
  - Monitors job throughput, campaign performance, and meetings created.

## 3. Core User Flows

1. **Configure & start a scrape**
   - Select counties
   - Toggle “AI enhancement”
   - Start scrape and see basic status.

2. **Review & deduplicate records**
   - View new records with AI-generated risk and categories.
   - See duplicate suggestions and merge/dismiss them.

3. **Launch outreach & schedule consults**
   - Sync high-priority records into CRM prospects.
   - Discover additional contact data (PhantomBuster).
   - Send outreach sequences.
   - Book consults via Calendly.

4. **Monitor performance**
   - Stats: record counts, exports, AI coverage.
   - Analytics: distributions by county, score, charge type, job volume.

## 4. Non-Functional Requirements

- Single Replit workspace, Node 20 + Postgres (Neon).
- Endpoints respond in < 1s under normal load.
- Scrape jobs and AI enrichment are asynchronous and resilient to failures.
- Basic error surfaces in the UI (with retry guidance).

## 5. AI Enhancement Overview

- **Charge Classification** – categorize charges into violent, property, drug, traffic, etc.
- **Risk Level** – infer low/medium/high based on charges + bond.
- **Normalization** – transform messy charge text into standardized descriptions.
- **Lead Scoring Input** – AI features feed into the lead scoring algorithm.

> Detailed behavior per feature is in individual Feature PRDs.

# Feature PRD – Lead Scraping & Intake

## Problem

Attorneys cannot manually monitor every county jail page for new arrests.
They need reliable, automated ingestion of fresh records, normalized and
ranked for follow-up.

## Goals & Success Metrics

- Start a scrape in < 30 seconds.
- See results ingested within minutes.
- Maintain > 95% success rate on supported county scrapes.

Success Metrics:

- Time from arrest to lead visibility.
- Number of successfully scraped records per run.
- % of records with AI enrichment.

## User Stories

- “As an intake specialist, I want to select one or more counties and start
  a scrape so I always see the latest arrests.”
- “As an attorney, I want to see risk level and charge categories so I can
  focus on high-value leads.”
- “As an operator, I want insight into recent jobs and failures.”

## UX Notes

- **Scrape Wizard**
  - Step 1: County selection (checkbox list from `FLORIDA_COUNTIES`).
  - Step 2: AI toggle (default ON).
  - Step 3: Confirmation + estimated completion time.
- **Job List**
  - Table with job ID, counties, status, recordsFound, aiEnhanced, lastUpdated.
- **Record List**
  - Filter by county/date/score.
  - Badges for risk level (“High Priority”, etc.)

### States

- Loading: skeleton rows while jobs/records load.
- Empty: helpful copy (“No records yet — start your first scrape.”).
- Error: toast + inline message with retry link.

## Data Model

- `arrest_records`
  - id, fullName, bookingDate, charges, bondAmount, county
  - ai fields: confidenceScore, chargeCategories, normalizedCharges, riskLevel

- `scrape_jobs`
  - id, jobId, counties, status, recordsFound, aiEnhanced, aiProcessed, errorMessage

## API Contract (High-Level)

- `POST /api/scrape/start`
  - Body: `{ counties: string[], enableAI: boolean }`
  - Response: `{ jobId: string, message: string, estimatedTime: string }`

- `GET /api/scrape/jobs`
  - Response: `ScrapeJob[]`

- `GET /api/scrape/status/:jobId`
  - Response: `ScrapeJob` with status & counts.

- `GET /api/records`
  - Query: `county?`, `dateFrom?`, `dateTo?`, `search?`, `page?`, `pageSize?`
  - Response: `{ records: ArrestRecord[], total: number }`

## AI Behaviors

- On scrape completion, run `enhanceRecordsBatch(records)` via `ai-service.ts`.
- AI should:
  - Assign a confidenceScore (0–100).
  - Classify chargeCategories.
  - Set riskLevel (low/medium/high) based on charges & bond.

## Analytics & Telemetry

- Count of records per scrape, per county.
- % scraped records with AI enrichment.
- Error reasons for failed counties (network, HTML change, etc.).

    expect(score).toBeLessThan(40);
  });
});
